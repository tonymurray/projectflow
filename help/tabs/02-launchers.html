Launchers

The Shortcuts column: categorized buttons that open files, folders, websites, and commands.

Launcher items

Every shortcut is a small triple: a display name, a path (a file, folder, URL, or command), and an application that decides how it opens — a specific program (firefox, gwenview), a generic handler (default, file_manager), or a more complex one that runs a command (npm, ssh_session, terminal). See the Examples tab for the full list with copy-paste patterns.

Items live in categories — plain named groups you create, rename, delete, and reorder. Drag an item to reorder it within a category, or drag it onto a different category's header to move it there.

Adding and editing

Click + Add in the launcher header for a quick-add dialog targeting the first category, or use ✏️ Edit Project for full editing — add categories, add entries per category, and edit/delete existing ones. A search box above the list filters visible items live as you type, matching name, path, or application.

alias and run — command launchers

These two types execute a command rather than opening a file. Both route into the built-in Terminal viewer by default when it's available (a small "$_" icon next to the item opens an external terminal instead).

  • alias — path format is alias_name command_or_directory. The first word becomes both the display name for status messages and a real bash alias exported to a shared aliases file you can source from ~/.bashrc.
  • run — path is a script or command run exactly as typed, e.g. ~/Programs/nixupdate.sh --check. Not exported as a shell alias — just a per-launcher convenience.

A safety note: naming an alias after a real shell command (most importantly cd) is a genuine footgun — bash appends your typed argument onto the alias's own command, so aliasing cd to cd ~/some_folder silently breaks every later bare cd <dir> elsewhere in the same shell ("too many arguments"). ProjectFlow checks the name you type against your real shell and warns you before this happens — redefining an alias you already made yourself (like ls → ls -altr) is fine and isn't flagged.

Grouping: Docs and Resources

Turn on ☰ Group (Standard layout) or use the Docs/Resources tabs (Focus layout) to split your categories into two views: a Docs bucket backed by one real "Documentation" category, and everything else under Resources. Where an item shows up is simply wherever it's physically filed — moving it (drag, or right-click "Move to category") is the only way to change which side it's on.

An automatic AI bucket appears above Docs if the project's folder has an ai/ subfolder or root files like CLAUDE.md/AGENTS.md — purely informational, nothing is written to your config for it.

Kickstart

🚀 Kickstart (in Project Settings, or automatically after creating a project from a folder) scans a project's folder and suggests documentation files, dev shortcuts, detected package-manager commands (npm/pip/cargo/go/composer), a project alias, and an optional website — all shown unchecked in a review dialog. Nothing is written until you check what you want and click Apply.

"Open All" — an opt-in guardrail

A category header can optionally get an ⚡ Open All button that fires every item in it at once. It's opt-in per category (right-click the header → "Enable Open All") and off by default — even for Documentation — since a single click firing an arbitrary mix of items is a real risk once alias/run items can execute commands. Even once enabled, if a category's contents include anything that runs a command, you get a one-line confirmation naming exactly what will run before it proceeds.
