Settings

Two different places to configure things: global, machine-wide settings, and each project's own settings.

Global Settings dialog

Open via the ⚙️ Settings button in the footer. Five tabs:

  • Settings — theme, startup behavior, notes folder, default application for new launchers, and general app-wide preferences.
  • Applications — your preferred editor, file manager, and terminal (auto-detected from your desktop environment if left blank).
  • Integrations — Kimai, Joplin, and Baloo File Tags (see the Integrations tab of this guide).
  • Icons — manage the application-icon mappings used throughout the launcher column.
  • Launch Handlers — create, edit, or override launch handlers (see the Examples tab for the built-in ones).

Project Settings

Click ✏️ Edit Project to open a project's own settings — a persistent form covering everything specific to just that project:

  • Name, color, and layout (Standard vs Focus)
  • Default Launcher Tab and Default Viewer Tab (what this project opens to)
  • Pinned PDF/Web/Image content, Terminal Path, and Folder Start Path
  • Scan for Documents and 🚀 Kickstart (see the Launchers tab)
  • An Integrations section: linked Kimai project, the per-project Baloo tag button, and Desktop Menu Entry (creates a .desktop file for this project in your application menu)

Per-project overrides for Terminal and Browser Links were removed in favor of always using the global Settings values — one less place to look when something doesn't behave as expected.

Where things are saved

Global settings live in .projectflow_settings.json next to the app. Each project is its own JSON file (or a hidden .projectflow file inside a project folder) — plain text, safe to back up, sync, or inspect directly if you're curious what a setting actually looks like on disk.
