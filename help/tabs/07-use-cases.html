Worked examples of setting up a real project end to end.

Personal Website

A typical small web project: a static or npm-built site living in ~/projects/personal-site, deployed somewhere, with a domain and hosting dashboard to check occasionally. Here's how that might come together in ProjectFlow.

1. Start from the folder

Open the Files tab (Focus layout) or the Folder Browser, navigate to ~/projects/personal-site, and click Make Project. This creates a bare project pointed at that folder and immediately opens the 🚀 Kickstart dialog.

2. Let Kickstart do the boring part

If the site has a package.json, Kickstart detects it and offers npm install, npm start/dev, and npm build shortcuts, plus a combined Directory Dev launcher (file manager + terminal + editor in one click). It also scans for a README.md and offers a project alias — check the box, name it something like site, and site becomes a real shell command that cds straight into the folder from any terminal, once you've sourced the generated aliases file. Review what's checked and click Apply — nothing is written until then.

3. Add what Kickstart couldn't know about

Use + Add or a category's own "+" to add things specific to this site:

  • A Resources entry for the live site URL (app: firefox) and the hosting provider's dashboard
  • An alias launcher for a deploy command, e.g. ["Deploy", "deploy ~/projects/personal-site && ./deploy.sh", "alias"]
  • A tail_log entry if the host writes an error log you check when something breaks

4. Pin what you look at most

Load the live site in the Web viewer and click its 📌 to make the Web tab open there by default, or pin the Editor to a specific file (like the main stylesheet) you're always tweaking. Set Default Viewer Tab in Project Settings so the project opens straight to whichever viewer you actually work in first.

5. Keep running notes

Use the Notes panel as a running list: design ideas, a content TODO, credentials reminders (not passwords!), or a changelog of what you last deployed and when. It autosaves as you type — nothing to remember to save.

The same pattern applies elsewhere

This isn't specific to code — the same shape (a folder or set of links, a few launcher categories, an alias for the common command, running notes) works just as well for a WordPress client site, a quarterly admin task like filing a VAT return, a backup routine, or a hobby you're learning. See the Introduction tab for the philosophy behind treating all of these as "projects" the same way.
