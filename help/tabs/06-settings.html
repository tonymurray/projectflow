Settings

Two different places to configure things: global, machine-wide settings, and each project's own settings.

Global Settings dialog

Open via the ⚙️ Settings button in the footer. Five tabs:

  • Settings — theme, startup behavior, notes folder, default application for new launchers, and general app-wide preferences.
  • Applications — your preferred editor, file manager, and terminal (auto-detected from your desktop environment if left blank).
  • Integrations — Kimai, Joplin, and Baloo File Tags (see the Integrations tab of this guide).
  • Icons — manage the application-icon mappings used throughout the launcher column.
  • Launch Handlers — create, edit, or override launch handlers (see the Handlers tab for the built-in ones).

Relocatable Data Folders

By default, your projects, notes, documents, and images all live inside ProjectFlow's own install folder. The Settings tab has a "Project Data Folder" section to move any or all of them to a network or cloud-synced folder instead (e.g. Nextcloud), so your data follows you across computers.

  • Project Data Folder — the simple option. Point this at one shared folder (e.g. ~/Nextcloud/ProjectFlow) and projects/notes/documents/images all live under it, created automatically if it doesn't exist yet.
  • Advanced: configure each location separately — a checkbox that reveals four individual folder fields, for when one location isn't enough. A common case: pointing Notes at a Nextcloud Notes app's own folder specifically, so your notes also show up there, while Projects/Documents/Images still share the one Project Data Folder above. An individual override always wins over the shared folder.
  • 📋 Copy Existing Data to New Location(s) — after pointing a field at a new folder, click this to copy (never move or delete) whatever you already have into the new location. Useful if you already created a few projects locally before deciding to switch to a synced folder. Your originals are left untouched — once you've confirmed everything works in the new location, go back and rename or move the old folder(s) yourself to avoid confusion between two live copies.

Changing a location only affects where ProjectFlow looks/writes going forward — nothing is moved automatically unless you click Copy Existing Data.

Project Settings

Click ✏️ Edit Project to open a project's own settings — a persistent form covering everything specific to just that project:

  • Name, color, and layout (Standard vs Focus)
  • Default Launcher Tab and Default Viewer Tab (what this project opens to)
  • Pinned PDF/Web/Image content, Terminal Path, and Folder Start Path
  • Scan for Documents and 🚀 Kickstart (see the Launchers tab)
  • An Integrations section: linked Kimai project, the per-project Baloo tag button, and Desktop Menu Entry (creates a .desktop file for this project in your application menu)

Where Project settings are saved

Global settings live in .projectflow_settings.json next to the app. Each project is its own JSON file, in the sub-directory 'projects', or the directory you specify in the settings (or, for 'Project Folders', in a hidden .projectflow file in the directory itself). The format is plain text JSON. The settings files can be backed-up or edited directly.

Direct editing

For advanced or adventurous people, you can directly edit project settings files and the main settings. Direct JSON editing is useful for bulk changes, such as adding many entries quickly, provided valid JSON is saved. See for example Editing JSON with Visual Studio Code or MDN: Working with JSON. Make a backup first, if the direct edit goes wrong, you can restore it.
