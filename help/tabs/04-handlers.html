Launch Handler Examples

In ProjectFlow 'handler' is the mechanism for creating a button launcher - a shortcut to a website, directory, file, note, or routine. Every entry in a project's launcher list uses the format ["Display Name", "path/arguments", "handler"]. This page shows what each handler expects, and how to create a custom handler.

Simple Handlers

Defined in launch_handlers.py — these execute a specific command with the path as an argument.

Firefoxfirefox
Opens a URL in the web viewer, or externally in Firefox browser.
Example:
["Wikipedia", "https://wikipedia.org", "firefox"]
Simple
Chromechrome
Opens a URL in the web viewer, or externally in Chrome.
Example:
["Google", "https://google.com", "chrome"]
Simple
Tail Logtail_log
Opens a terminal and tails a log file. Pass a directory to auto-detect the log file (prefers debug.log, falls back to error.log), or a full path to tail a specific file.
Examples:
["Watch Logs", "~/projects/myapp", "tail_log"]
["Watch Error Log", "~/somewhere/error.log", "tail_log"]
Simple
Kitty Tailkitty_tail
Same as tail_log but uses the kitty terminal with --hold to keep the window open.
Example:
["Watch Logs (Kitty)", "~/projects/myapp", "kitty_tail"]
Simple

Built-in Handlers

Always available. These use your default desktop applications.

Browserbrowser
Opens URLs in your default web browser using xdg-open.
Example:
["Documentation", "https://docs.python.org", "browser"]
Built-in
File Managerfile_manager
Opens folders in your default file manager (Dolphin, Nautilus, etc.).
Example:
["Downloads", "~/Downloads", "file_manager"]
Built-in
Editoreditor
Opens files in your default text editor.
Example:
["Config File", "~/.bashrc", "editor"]
Built-in
Defaultdefault
Lets the system decide how to open the file, based on its type.
Example:
["Spreadsheet", "~/Documents/budget.xlsx", "default"]
Built-in
Terminalterminal
Opens a terminal at the specified directory with an optional command. Also available as konsole.
Examples:
["Project Terminal", "~/projects/myapp", "terminal"] -> opens terminal at ~/projects/myapp ["Run Script", "~/project ./go.sh", "terminal"] -> cd ~/project && ./go.sh ["Dev Server", "~/project npm run dev", "konsole"] -> cd ~/project && npm run dev
Built-in

Complex Handlers

Handlers with extra logic built in — most accept additional arguments after the path.

NPMnpm
Run npm commands in a terminal. Append the command after the path. Commands: start, dev, build, test, install, or any script name.
Examples:
["Start Server", "~/projects/myapp", "npm"] # npm start ["Dev Server", "~/projects/myapp dev", "npm"] # npm run dev ["Build", "~/projects/myapp build", "npm"] # npm run build ["Run Tests", "~/projects/myapp test", "npm"] # npm test ["Install Deps", "~/projects/myapp install", "npm"] # npm install
Complex
Shell Aliasalias

The idea behind including shell aliases in ProjectFlow, is to link aliases to projects yet make them available in your regular terminal too

Runs a command in a terminal (or opens a terminal at a directory) AND exports a bash alias to projects/projectflow_aliases. Source that file from ~/.bashrc to use the same shortcuts in any terminal session.

Path format: alias_name command_or_path — the first word becomes the bash alias identifier; everything after is the command or directory. See the Launchers tab for a real footgun this handler can create (aliasing a real shell command like cd) and the built-in warning that catches it.
Examples:
["Git Status", "gs git status", "alias"] ["Rebuild NixOS", "rebuildnix sudo nixos-rebuild switch", "alias"] ["Music Folder", "music ~/Music", "alias"] ["Dev Server", "dev npm run dev", "alias"]
Generated aliases file lines:
alias gs='git status'
alias music='cd ~/Music'

To activate in your desktop terminal application, add to ~/.bashrc:
if [ -f ~/path/to/projects/projectflow_aliases ]; then source ~/path/to/projects/projectflow_aliases fi


If you stop using aliases in ProjectFlow, you can cut/copy collected aliases from projects/projectflow_aliases into your ~/.bashrc file
Complex
Runrun
Runs a script or command exactly as typed — the whole path IS the command. Unlike alias, nothing is exported to the shell-alias file; this is a per-launcher convenience only.
Example:
["Check for Updates", "~/Programs/my_script.sh", "run"]
Complex
Directory Devdirectorydev
Opens a full development environment: file manager + terminal + code editor. Optionally runs npm if a command is specified.
Examples:
["My Project", "~/projects/myapp", "directorydev"] # 3 apps, no npm ["My Project", "~/projects/myapp dev", "directorydev"] # + npm run dev ["My Project", "~/projects/myapp build", "directorydev"] # + npm run build
Complex
SSH Sessionssh_session
SSH to a server with optional path and command. If the second part starts with /, ~, or . it's treated as a path.
Examples:
["Server", "user@host", "ssh_session"] -> ssh user@host ["Server", "user@host /var/www", "ssh_session"] -> ssh user@host 'cd /var/www && bash' ["Server", "user@host /app ./go.sh", "ssh_session"] -> ssh user@host 'cd /app && ./go.sh' ["Server", "user@host npm start", "ssh_session"] -> ssh user@host 'npm start'
Complex
Terminal Commandterminal_cmd
Open a terminal at a directory with an optional command. Same syntax as ssh_session but for local paths.

Unlike the run command above — which treats the whole path as the command — here the first token is the directory, and any remaining (optional) tokens form the command to run inside it. If no command is given, a plain shell opens at that directory instead.
Examples:
["Project", "~/project", "terminal_cmd"] -> opens terminal at ~/project ["Run Script", "~/project ./go.sh", "terminal_cmd"] -> cd ~/project && ./go.sh ["Dev Server", "~/project npm run dev", "terminal_cmd"] -> cd ~/project && npm run dev
Complex
Dolphin Tabsdolphin_tabs
Opens multiple folders as tabs in your file manager. Paths are space-separated.
Example:
["My Folders", "~/Documents ~/Projects ~/Pictures", "dolphin_tabs"]
Complex
Rsync Backuprsync_backup
Run rsync with --delete and safety checks. Backs up deleted files to ~/.rsync_backups/. Blocks trailing slashes on the source, and uses the flags a (archive), v (verbose), and z (compress). It also passes --info=progress2 which shows an overall transfer-progress summary rather than per-file output.
Example:
["Backup Docs", "~/Documents ~/backup/Documents", "rsync_backup"]
Complex
Rsync + Identityrsync_backup_id
Rsync with an SSH identity file. Format: identity_file source destination.
Example:
["Backup to Server", "~/.ssh/key ~/local user@server:/remote", "rsync_backup_id"]
Complex
Rsync + Identity + Portrsync_backup_id_port
Rsync with an SSH identity file and custom port. Format: identity_file port source destination.
Example:
["Backup via Port 2222", "~/.ssh/key 2222 ~/local user@server:/remote", "rsync_backup_id_port"]
Complex

Custom Handlers

User-defined handlers stored in launch_handlers_custom.json. Create and edit via Settings → Launch Handlers. Custom handlers can override built-in ones.

Example: My Terminalmy_terminal
Open Alacritty at a directory.
JSON Definition:
{ "my_terminal": { "command": ["alacritty", "--working-directory", "{path}"], "description": "Open in Alacritty" } }
Custom
Example: Deploy Scriptdeploy
Run a deploy script in a terminal.
JSON Definition:
{ "deploy": { "type": "shell", "command": "cd {path} && ./deploy.sh", "terminal": true, "hold": true, "description": "Run deploy script" } }
Custom

Example - adding a custom handler for Email links

Challenge - task

It is sometimes time-consuming to find an exact email message related to a problem. It would be useful to be able to add a ProjectFlow launcher to open your email program with the message displayed.

Approach

Web search shows that both online Gmail and Thunderbird can be configured to point to particular emails based on their unique MessageID

Thunderbird works as-is with instructions below, Gmail requires a custom handler in Settings

Thunderbird

Option 1 - built in support for mid protocol

Thunderbird has built in support for the Message ID protocol:

You can imediately test linking to a specific email by:

  1. In Thunderbird, select a message, in the message pane: choose 'more' (top-right), 'copy message link' (then close the application)
  2. In ProjectFlow, add a new launcher, Enter Title "Test Email", path: [the message link, copied previously: mid:010101xxxx@example.com]], and application 'thunderbird'
  3. Save and test that the link opens the email in Thunderbird

Gmail — worked example of adding your own custom handler

Gmail has no mid: protocol registration, but it does support a search operator, rfc822msgid:, that jumps straight to a message by its Message-ID — so the same mid: link you copied from Thunderbird above can drive a second launcher, this time opening the message in Gmail instead. Unlike Thunderbird's built-in mid: support, no application already understands this, so there's no ready-made handler for it — a good excuse to build a custom handler from scratch and see how the pieces fit together.

The handler needs to do two small things a built-in handler can't: strip the leading mid: prefix off the launcher's path, and build a Gmail search URL around what's left. A shell-type custom handler can do both in one command.

Open Settings → Launch Handlers → Add Handler and fill in the fields exactly as below:

The Add Handler dialog, filled in for gmail_msgid
Handler Name
gmail_msgid
Command
Type this exactly as shown — plain " characters, not escaped. (The dialog's Command field stores whatever you type as a plain string; escaping is only something a raw launch_handlers_custom.json file needs, not this box.)
xdg-open "https://mail.google.com/mail/u/0/#search/rfc822msgid:$(printf '%s' '{path}' | sed 's/^mid://')"

Explanation of the code

xdg-open: A desktop standard command to open the default application (in this case a web link to Gmail) in your default browser

The final URL is [Gmail search] + the message ID, with the following modifications:

  • Start with the Gmail search URL: https://mail.google.com/mail/u/0/#search
  • Add the Gmail-specific search string: /rfc822msgid:
  • {path} is the message ID copied from Gmail
  • Ensure the message ID has the mid: part removed (sed 's/^mid://')*
  • Re-add it to the URL

*Click here for an explanation of the SED command

Type
shell
Run in terminal / Keep terminal open
Leave both unchecked. This command just resolves a URL and hands off to xdg-open in the background — there's nothing for a terminal window to show, so checking either just makes one flash open for no reason.
Description
Open a Gmail message by its Message-ID (mid: link)
Example
Just the path portion — shown back to you as placeholder text in a launcher's Path field, not a full launcher item.
mid:010101xxxx@example.com

Click OK, then Apply/OK on the Settings dialog. gmail_msgid now shows up in the Application dropdown for any launcher, tagged Custom in the Launch Handlers list.

Test your new launcher

  1. Open Gmail in your browser and select an email.
  2. With the message open, click the ⋮ (three-dot) menu and choose "Show original" — second-last option in that menu.
  3. On the page that opens, copy the Message-ID value from the raw headers, then close that window — that's all you needed from it.
  4. In ProjectFlow, add a new launcher: a Title of your choosing, the Message-ID you just copied as the path (with or without the mid: prefix — gmail_msgid's sed only strips it if it's there, so either form works), and gmail_msgid as the application.
Adding the test launcher with the copied Message-ID

Save and test — it should open your default browser at a Gmail search that lands directly on that message.

Notes: this only finds the message if it exists in the Gmail account signed in at /mail/u/0/ (the first/primary account slot) — swap the 0 for another index if you use a different account for this project. It's also a plain shell command built around whatever you paste in, not hardened against unusual characters in a Message-ID — fine for a personal launcher you're pointing at your own links, not something to expose to untrusted input.
